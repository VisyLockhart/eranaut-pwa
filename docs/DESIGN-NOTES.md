# Design notes

程式碼註解裡的 `D-xx`、`R-xx`、`SCHEMA §x` 是作者在開發期間維護的設計文件編號:

- **`D-xx`**:一條已拍板的設計決策(Decision),附理由。例如 `D-125` 是「OCR 引擎選 PP-OCRv4」。
- **`R-xx`**:被否決的方案(Rejected)與否決原因,避免重複討論同一個點子。
- **`SCHEMA §x`**:資料表與 API 契約文件的章節。

這些原始文件沒有隨 repo 公開(其中夾雜社群內部的細節)。這裡只摘要與程式碼最相關的決策,方便讀者理解註解的出處。型別層面的 API 契約都在 [`shared/src/api.ts`](../shared/src/api.ts)。

更完整的設計脈絡(試過什麼、為什麼放棄、取捨)請看 [`ARCHITECTURE.md`](ARCHITECTURE.md)([English](ARCHITECTURE.en.md))。

## 架構與資料

| 編號 | 決策 |
|---|---|
| D-10 | 所有資料存取經過同一個 API;Discord bot 也呼叫 API,不直接開 SQLite。原因:`better-sqlite3` 同步寫入,多個 process 同寫一個檔案會出問題,入口唯一也好稽核。 |
| D-22 | 後端用 Node.js + TypeScript + Fastify。 |
| D-131 | API 同一程序開兩個埠:公開埠給網站、內部埠給 bot(共用密鑰 Bearer 認證,不對外發佈)。兩者共用同一層 service / repository,差別只在認證與身份解析。 |
| D-136 | 所有資料表主鍵用 UUID v4(存 TEXT),不使用自動遞增整數。 |
| D-140 | 前後端放同一個 monorepo(npm workspaces:`api/`、`web/`、`shared/`),型別與固定常數只維護一份。 |
| D-141 | 前端用 Angular;PWA 的 service worker 只快取 app shell,API 一律 network-only。 |
| D-146 | 總覽用單一 `GET /api/overview` 一次取得所有工坊與潛艇,避免前端打 N 次請求。 |

## 認證與權限

| 編號 | 決策 |
|---|---|
| D-35 | 登入 session 採伺服器端 session cookie(DB 只存雜湊),不用 JWT + refresh token:單一 API 加 SQLite,無狀態驗證的優勢用不上,而且 session 可以即時撤銷。 |
| D-142 | 前端與 API 同網域、不做 CORS;cookie 用 `SameSite=Lax`;GET 端點不得有副作用;改資料的請求檢查 `Origin`;不做 CSRF token、不加 PKCE。 |
| D-143 | 「有資格的身份組」可設多個,規則用字串表達:`,` 為或、`+` 為且,例如 `A+B,C` = (A 且 B)或 C。規則只定義在 API 一處,網站登入、每日比對、bot 指令共用同一個判斷函式。 |
| D-130 | 失去資格(離開伺服器、被移除身份組)時標記停用而非刪除資料;每天比對一次成員名單,登入時另有一次即時檢查。 |

## OCR 與提醒

|---|---|
| D-125 | OCR 自架,不連外部服務;引擎用 PP-OCRv4(`@gutenye/ocr-node`),與 API 同一個 process。 |
| D-126 | 上傳的截圖辨識完不存檔,全程只在記憶體,因此不需要圖片回收排程。 |

## 航線模擬器

`RS-nn` 即 `D-(178+nn)`(航線模擬器的設計紀錄先以 `RS-xx` 編號,之後併入 D 編號)。

| 編號 | 決策 |
|---|---|
| D-202(RS-24) | 航點、物品、配件與等級表打包進航線頁的 lazy chunk,不查詢、不進資料庫;由 service worker 一起快取,離線可用,更新靠重新部署。 |
| D-203(RS-25) | 「儲存配置」存資料庫(`route_subs`)、跨裝置同步,每位使用者最多 10 組;只有檢視狀態(海域、已選航點、臨時配置)留在各裝置的 `localStorage`。 |
| D-217 | 一組配置可綁多艘工坊潛艇(`route_sub_bindings`,一艘潛艇只綁一組,兩邊 CASCADE,不需清理排程);舊的單艘欄位不再讀寫(SQLite 不能直接 DROP 有外鍵的欄位)。 |
| D-229 / D-230 | 找路線的「條件組合」:命名儲存的篩選條件,存資料庫(`route_filters`,JSON 欄位 `spec`,每人最多 10 組)、跨裝置同步;不存配置與去過的航點,載入時整組套用、不判斷符不符合;從列上選一組會自動搜尋並收合海圖與條件區。展示版由展示用後端在瀏覽器模擬(D-292)。 |
| D-168 | 展示模式:建置時用 `fileReplacements` 換上假的 `HttpBackend`;航線模擬在展示版以 `ROUTE_FEATURES` 關掉「儲存配置」與「綁定工坊潛艇」。 |

## 配件製作

| 編號 | 決策 |
|---|---|
| D-258 | 結果分成三份**等價**的清單:交納素材(配方上的數量,對應遊戲交納畫面)、直接素材(把還沒備齊的交納素材各做一輪所需的半成品與素材)、基礎素材(完整展開)。使用者單看任何一份,要準備的東西都一樣多。同一個品項可以同時在交納與直接素材出現(白鋼錠:要交 54、做鉚釘又要 54)。 |
| D-258 | 庫存逐層連動,直接併進計算函式 `calculate(選擇, 選項, 資料, 庫存)`:上層備齊,下層需求相應扣除,清掉庫存就自動回來;列一律保留(需求 0 顯示 ✓)。備料進度只看交納素材,避免被素材的龐大數量稀釋。庫存鍵:同名品項在交納與直接素材各記各的(直接素材裡的可製作品用 `d:` 前綴),否則同一批庫存會被算兩次。 |
| D-257 | 資料集逐項對照第三方工坊計算器校正:40 種配件各取三份清單比對,修了來源資料 8 處錯誤。校正寫在資料產生腳本 `tools/craft-data/build.mjs` 的獨立區段,每項附前提檢查(來源改了會報錯),不手改產出的 JSON;比對的數字留成回歸測試(`craft-5p.spec.ts`)。 |
| D-259 | 清單可切換「按種類 / 按名稱」。名稱排序不是一般逐字排序:前兩個字相同的聚成一群(白鋼錠、白鋼鉚釘、白鋼連接板相鄰),群內字數少的先,再依筆畫;碎晶 / 水晶 / 晶簇維持遊戲內的元素順序。點一列追蹤時,被點的列與關聯項目移到各清單最上方的「追蹤」分類;開始追蹤自動捲到追蹤區、取消時還原捲動位置,避免列「飛走」讓人找不到原位。 |

## 前端細節

| 編號 | 決策 |
|---|---|
| D-157 | 本機開發轉發改用自製 Node 代理 `web/dev.mjs`:在 Windows 上 Vite 內建的 proxy 會間歇出現 `ECONNRESET`,自製版經實測沒有失敗。 |
| D-164 | 介面大小(小 / 中 / 大)用 CSS `zoom` 整體縮放;`vh` / `vw` / safe-area 長度要除以另一個變數 `--vu-div`,因為 Safari 與 Chrome 對 `zoom` 下這些單位的處理不同。 |
| D-166 | 手機留白縮小、統計區與桌機側欄可收合、手機總覽下拉重新整理。偏好只存在該裝置的 `localStorage`。 |
| D-260 | 新版橫幅除了依賴 service worker 的通知,另外直接向伺服器要最新的 `index.html`、比對主程式檔名。起因是 Angular service worker 一旦因檔案雜湊對不上進入降級狀態(`EXISTING_CLIENTS_ONLY`),就永遠不再通知新版,常開著的桌面 App 會一直停在舊版而沒有任何提示。按「立即更新」時若沒有可啟用的新版,先解除 service worker 並清掉它的快取再重載。 |
| D-261 | 設定頁(桌機)與右上角頭像選單(手機)加入「檢查更新」。按鈕只做檢查、不無條件重設 service worker:先問 service worker,再直接比對伺服器的主程式檔名,所以即使 service worker 已降級也找得到新版;找到就顯示「立即更新」橫幅,真的需要重設時才在使用者按橫幅時做(避免每次檢查都丟離線快取、中斷未存的輸入)。自動檢查保留。 |
| D-283 | 伺服器維護橫幅:Discord bot 從官方公告取得維護時段後經內部端點送進 API(連結只允許官網網址、標題限長),總覽回應一併帶出;前端在維護前與維護中顯示,色彩只用主題變數,四個主題共用。 |
| D-288 | 配件維修提醒:綁定配置的潛艇才能開啟;可跑趟數依路線與配件算出,每次「上一趟已返航又派出」計 1 趟,用滿後再出航視為已維修。規則放 `shared/upkeep.ts`,前後端共用。 |
| D-289 / D-291 | 等級與練級輔助:記錄等級(可由截圖辨識),派出時記下路線作為待結算經驗,返航後再派出才寫進等級;明確輸入等級或截圖辨識時舊的待結算作廢,避免重複加。「派出建議」在更新頁出發前算好下一趟:先照攻略的路線,走不了才在攻略出現過的航點裡依偏好的時間上限找經驗最多的;潛艇欄位還沒解鎖時,潛艇-1 優先建議含解鎖點的路線。純函式、結果記憶化。 |
| D-292 | 展示版同步上述功能:假資料放好練級中、需維修的潛艇與綁定的配置;展示用後端照正式版規則模擬計次、結算與配置儲存,資料存在瀏覽器;展示標籤可切換示範用的維護橫幅。 |

## 慣例

- 資料庫時間一律存 UTC,台北時間在 API / 前端層轉換。
- 資料以使用者為單位隔離,任何查詢都不跨使用者。
- Commit message 採 Conventional Commits,說明「為什麼」。
